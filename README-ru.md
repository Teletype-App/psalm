# Форк Psalm от Teletype

Это поддерживаемый форк [Psalm](https://github.com/vimeo/psalm), предназначенный для точного сопровождения PHPDoc с исключениями в больших PHP-приложениях и расширенного анализа Yii 2.

Общее описание Psalm, справочник конфигурации и инструкции по интеграции с редакторами находятся в [каноническом README upstream](https://github.com/vimeo/psalm/blob/master/README.md) и [документации Psalm](https://psalm.dev/docs). Здесь описаны только отличия форка.

Поддерживаемая ветка форка — [`teletype`](https://github.com/Teletype-App/psalm/tree/teletype). Ветка по умолчанию на GitHub пока остаётся `6.x`, поэтому после обычного клонирования нужно явно переключиться на `teletype`. Имя Composer-пакета осталось прежним — `vimeo/psalm`, но это не сборка upstream из Packagist.

## Отличия форка

| Область | Поведение форка | Практический результат |
| --- | --- | --- |
| Вывод исключений | Строит транзитивные сводки исключений по коду проекта с учётом цепочек вызовов, условий, catch/rethrow, замыканий, трейтов и статически разрешимого полиморфизма | `@throws` можно синхронизировать с реально проанализированным поведением, а не только с непосредственными аннотациями |
| Исправления Psalter | Добавляет, сужает и удаляет аннотации через `MissingThrowsDocblock`, `OverlyBroadThrowsDocblock` и `UnusedThrowsDocblock` | Один запуск приводит документацию исключений в соответствие с выбранным кодом |
| Анализ изменений Git | Добавлены `--changed`, `--base`, `--full-file`, `--report-changed` и совместный отчёт по неиспользуемым переменным | В большом репозитории можно изменять только затронутые объявления, продолжая анализировать их зависимости |
| Объяснение результата | Добавлен `--show-inferred-throws` | Показывает, почему исключение дошло до функции или метода: цепочку вызовов и известные условия |
| Кэш | Хранит сводки исключений с проверкой содержимого и зависимостей в обычном каталоге кэша Psalm | Повторный анализ переиспользует результаты незатронутых методов без изменения результата |
| API плагинов | Добавлены providers исключений методов и свойств, а также providers смешанного возвращаемого типа методов | Интеграции фреймворков могут описывать динамическую диспетчеризацию без анализа всех тел vendor-кода |
| Плагин Yii 2 | Понимает возвращаемые типы запросов ActiveRecord, relations, magic properties, lifecycle hooks, validation callbacks, завершающие DB-вызовы и отдельные динамические пути создания/присваивания | Уменьшает ложные ошибки и восстанавливает исключения, скрытые за runtime-соглашениями Yii |

Ни одна возможность upstream не заявлена как намеренно удалённая. Всё, что не перечислено выше, следует считать поведением upstream Psalm на коммите, который сейчас влит в эту ветку.

## Установка

До установки Psalm укажите Composer этот репозиторий:

```bash
composer config repositories.teletype-psalm vcs https://github.com/Teletype-App/psalm.git
composer require --dev vimeo/psalm:dev-teletype
```

Сохраняйте `composer.lock`: он фиксирует точную ревизию форка, даже когда `dev-teletype` продвигается. Релизы форка имеют теги вида `7.0.0-p46`; выбирайте подходящий тег, когда он уже содержит все нужные изменения.

Если установить `vimeo/psalm` из Packagist без VCS-репозитория, будет установлен upstream Psalm. Архивы релизов, PHAR, Docker-образы и self-update из инструкций upstream также не устанавливают этот форк.

## Анализ исключений и поддержка Yii

Включите проверку PHPDoc с исключениями и встроенный плагин Yii 2 в `psalm.xml`:

```xml
<psalm checkForThrowsDocblock="true">
    <plugins>
        <pluginClass class="Psalm\Plugin\Yii2\Plugin"/>
    </plugins>
</psalm>
```

Сначала просмотрите изменения PHPDoc для изменённого кода без записи файлов:

```bash
vendor/bin/psalter --changed --base=origin/develop --dry-run \
  --threads=1 --scan-threads=1 \
  --issues=MissingThrowsDocblock,OverlyBroadThrowsDocblock,UnusedThrowsDocblock
```

Чтобы применить изменения, уберите `--dry-run`. Флаг `--show-inferred-throws` у Psalm или Psalter показывает выведенные цепочки вызовов. Полное описание CLI и кэша форка находится в разделе [«Исправление кода»](docs/manipulating_code/fixing.md).

Для большого проекта с ограниченной памятью начинайте с одного процесса анализа и сканирования, как в примере выше, оставляйте кэш включённым и увеличивайте параллелизм только после замеров.

## Границы анализа

- Цели, известные только во время выполнения — произвольные callable-переменные, динамические имена методов, конфигурация service locator, behaviors и некоторые отложенные замыкания — не всегда разрешимы статически. Форк не перебирает все воображаемые цели и не сохраняет существующий `@throws` как fallback для неразрешённого ребра.
- Vendor-код обычно представлен объявленными контрактами. Недокументированное runtime-исключение зависимости невидимо, пока его не опишет точечный provider или stub.
- Поддержка Yii основана на соглашениях фреймворка и ограничена целями, которые можно разрешить без широкого анализа тел vendor-кода.
- Первый расчёт исключений может быть дорогим. Прерванный анализ не сохраняет частично сошедшиеся сводки.
- Кэш служит только оптимизацией; его инвалидация рассчитана на тот же результат, что и чистый запуск.

## Разработка и синхронизация с upstream

`origin` указывает на форк Teletype, а `upstream` — на канонический репозиторий Psalm. Обновляйте поддерживаемую ветку явным merge-коммитом, чтобы изменения форка и разрешение конфликтов оставались видимыми:

```bash
git fetch upstream
git switch teletype
git merge --no-ff upstream/master
composer install
composer tests
```

После каждого слияния проверяйте специфичные для форка тесты вывода исключений, кэша, Psalter и Yii. Не заменяйте поддерживаемую ветку содержимым upstream и не считайте, что релиз upstream включает изменения форка.

Основной набор тестов запускается на push и pull request. Некоторые унаследованные workflows для сборки артефактов работают только для `master`, `6.x` или событий release, поэтому push в `teletype` сам по себе не публикует все артефакты upstream.
